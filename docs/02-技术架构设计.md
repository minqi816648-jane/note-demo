### 1.2 架构设计原则

1. **本地优先 (Local-First)**：所有数据先写入本地 SQLite，云端同步为异步补充
2. **模块化设计**：功能模块独立，通过服务层通信
3. **可替换的 AI 服务**：AI 服务通过抽象接口调用，可随时切换不同提供商
4. **离线可用**：核心功能完全不依赖网络
5. **隐私保护**：敏感笔记标记后不离开本地设备

### 3.3 数据加密策略

| 场景 | 加密方式 | 说明 |
|------|----------|------|
| 普通笔记 | 不加密 | 明文存储，性能优先 |
| 敏感笔记 | SQLCipher 列级加密 | content 字段使用 AES-256 加密 |
| API Key | 系统安全存储 (Keychain/Keystore) | 不存数据库 |
| 待办提醒 | 不加密 | 仅存提醒时间戳 |
| AI 对话 | 可选加密 | 可通过设置开启 |

### 4.3 RAG 检索流程

```
┌────────────────────────────────────────────────────────────────────┐
│                         RAG 检索流程                                │
│                                                                     │
│  用户提问 ──▶ 问题预处理 ──▶ 向量化 ──▶ 向量检索 ──┐                   │
│                                                    ▼               │
│  检索结果 ──▶ 重排序 ──▶ 上下文组装 ──▶ Prompt ──▶ LLM 回答        │
│                                                    │               │
│  关键词检索 ──▶ FTS5 全文搜索 ──┐                     ▼               │
│                                ├────▶ 结果合并    用户得到答案      │
└────────────────────────────────────────────────────────────────────┘

步骤说明：
1. 向量化：使用 BGE-M3 本地模型将查询转为 1024 维向量
2. 向量检索：在 FAISS 索引中查找 Top-K 相似笔记片段
3. 关键词检索：同时使用 SQLite FTS5 进行全文关键词匹配
4. 结果合并：向量结果 + 关键词结果按相关性加权合并
5. 重排序：基于 BM25 + 向量余弦相似度的组合分数重排
6. 上下文组装：取 Top-5 笔记内容拼接到 System Prompt
7. LLM 回答：AI 基于上下文精准回答用户问题
```

### 5.2 向量索引策略

| 项目 | 方案 |
|------|------|
| 嵌入模型 | BGE-M3 (轻量版) - 本地 ONNX 运行 |
| 向量维度 | 1024 维 |
| 索引库 | FAISS (移动端 WASM/C++ 编译) |
| 分块策略 | 按段落/句分块，保留元数据关联 |
| 索引更新 | 笔记保存/编辑时增量更新 |
| 与 FTS5 配合 | 同时索引，结果按权重融合 |

## 6. 同步与后端架构

### 6.1 同步策略

```
┌──────────────┐         ┌──────────────┐         ┌──────────────┐
│   本地 SQLite  │         │ 同步队列      │         │ 云端服务器    │
│              │         │ (本地)       │         │              │
│  笔记/待办/   │         │ 变更时间戳    │         │ PostgreSQL   │
│  对话/链接    │────────▶│ 增量变更记录  │────────▶│ + MinIO/S3   │
│              │         │ 冲突标记     │         │              │
└──────────────┘         └──────────────┘         └──────────────┘
       ▲                        │                         │
       │                        │                         │
       └────────────────────────┴─────────────────────────┘
                轮询拉取 + 推送变更

同步协议要点：
1. 每个实体带有 updated_at 时间戳和版本号
2. 支持增量同步 - 只传输变更过的记录
3. 冲突解决策略：
   - 相同实体冲突：后写入者胜 (LWW)
   - 敏感笔记：永不冲突，不上传不更新
   - 删除冲突：删除优先
4. 离线队列：断网时持续在本地队列缓存操作，联网后批量同步
5. 同步压缩：使用 gzip 压缩传输，减少流量
```

## 8. 性能架构

### 8.1 性能优化策略

| 维度 | 优化策略 | 预期效果 |
|------|----------|----------|
| **启动速度** | 懒加载路由、延迟初始化非核心服务 | 冷启动 < 3秒 |
| **列表滚动** | FlatList 虚拟化、图片懒加载 | 60fps 流畅滚动 |
| **笔记加载** | SQLite 索引优化、查询缓存 | < 100ms |
| **AI 响应** | 流式输出、结果缓存、请求合并 | 首字 < 2秒 |
| **图片处理** | 压缩后存储、缩略图缓存 | 加载 < 200ms |
| **语音识别** | 流式识别、实时展示 | 边录边转 |
| **搜索** | FTS5 索引 + 向量缓存 | < 500ms |
| **网络** | 请求合并、图片 CDN、数据压缩(gzip) | 减少 50% 流量 |

### 8.2 缓存策略

```
┌────────────────────────────────────────────────────┐
│                    缓存层级                          │
│                                                      │
│  ┌────────────────────────────────────────────┐   │
│  │ 内存缓存 (Zustand + react-query)          │   │
│  │ - 当前列表数据                             │   │
│  │ - 最近打开的笔记                           │   │
│  │ - AI 对话上下文                            │   │
│  └────────────────────────────────────────────┘   │
│  ┌────────────────────────────────────────────┐   │
│  │ 本地缓存 (SQLite + 文件系统)              │   │
│  │ - 全量数据（本地优先主存储）              │   │
│  │ - 图片缩略图缓存                          │   │
│  │ - 向量索引                                │   │
│  └────────────────────────────────────────────┘   │
│  ┌────────────────────────────────────────────┐   │
│  │ 远程缓存 (CDN + Redis)                    │   │
│  │ - 分享链接预览数据                         │   │
│  │ - 公共资源文件                             │   │
│  └────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────┘
```

### 8.3 内存管理

- 图片使用三级缓存（内存 + 磁盘 + 网络）
- 富文本编辑器限制历史快照数量（最多 50 个）
- 音频播放完毕立即释放资源
- 大量笔记列表使用分页加载（每页 50 条）
- 向量搜索索引控制在 50MB 以内，超出自动精简

## 9. 错误处理与异常恢复

### 9.1 错误分类与处理策略

| 错误类型 | 处理策略 | 用户提示 |
|----------|----------|----------|
| 网络错误 | 自动重试 (最多3次)，降级到离线模式 | 显示离线状态 |
| AI 服务错误 | 切换备选 Provider，记录错误日志 | 友好提示 + 重试按钮 |
| 数据库错误 | 事务回滚，保留用户数据 | 提示保存失败+重试 |
| 图片加载失败 | 显示占位图，提供重新加载 | 图片加载失败提示 |
| 语音识别失败 | 手动输入作为备选 | 提示转写失败+可手动输入 |
| 同步冲突 | 自动合并或提示用户选择 | 冲突解决界面 |
| API Key 无效 | 检测并提示重新配置 | 跳转设置页 |
| 存储空间不足 | 尝试自动清理缓存 | 提示清理建议 |

### 9.2 崩溃恢复

```
崩溃捕获 → 异常日志上报 (可选) → 本地数据一致性检测
    │                      │                        │
    ▼                      ▼                        ▼
  用户友好提示        崩溃日志存入本地          数据库完整性校验
    │                                            │
    └──────────── 自动恢复 ──────────────────────┘
              - 事务日志回滚
              - 临时文件清理
              - 索引重建 (如损坏)
```

## 11. 技术风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| AI 服务限流/宕机 | 核心功能不可用 | 多 Provider 切换，降级提示 |
| 本地模型体积过大 | APK 体积增大 | 模型按需下载，WASM 压缩优化 |
| SQLite 性能瓶颈 | 大量笔记时卡顿 | 索引优化、分页查询、定期 VACUUM |
| 富文本编辑器兼容性 | Android 机型差异 | 充分测试，自定义渲染兜底 |
| 系统分享不响应 | 分享功能失效 | 多种分享 Intent 注册，测试覆盖 |
| 同步冲突复杂性 | 数据不一致 | 简化冲突策略 (LWW)，提供手动合并 |
| AI 对话上下文超长 | Token 超限 | 上下文压缩、截断策略、分段处理 |
