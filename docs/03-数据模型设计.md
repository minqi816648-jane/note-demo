# note-demo 数据模型设计文档

## 1. 概述

本文档定义 note-demo 应用的全部数据模型，包括本地 SQLite 数据库表结构、字段设计、索引策略、数据关系及数据生命周期管理。

### 1.1 设计原则

1. **本地优先**：所有数据以本地 SQLite 为主存储
2. **软删除**：所有核心实体支持软删除（deleted_at 字段）
3. **时间戳**：所有表包含 created_at 和 updated_at 字段
4. **版本控制**：笔记支持版本历史管理
5. **完整性**：外键约束保证数据一致性
6. **加密**：敏感数据字段级加密存储

### 1.2 约定说明

- 所有表名使用小写复数形式
- 所有主键使用自增 INTEGER 或 UUID 字符串
- 时间字段统一使用 ISO 8601 格式（字符串存储）
- 布尔字段使用 INTEGER (0/1) 替代 SQLite BOOLEAN
- 加密字段以 _enc 后缀标记
- 软删除字段统一命名为 deleted_at

## 2. 核心表结构

### 2.1 笔记表 (notes)

```sql
CREATE TABLE notes (
    id              TEXT PRIMARY KEY,          -- UUID
    parent_id       TEXT,                      -- 所属文件夹 ID，NULL 表示根目录
    title           TEXT NOT NULL DEFAULT '',  -- 笔记标题
    content         TEXT DEFAULT '',           -- 富文本内容 (JSON格式)
    content_text    TEXT DEFAULT '',           -- 纯文本内容 (用于搜索)
    category_id     TEXT,                      -- 所属分类 ID
    ai_summary      TEXT,                      -- AI 生成摘要
    ai_tags         TEXT,                      -- AI 生成标签 (JSON数组)
    is_sensitive    INTEGER DEFAULT 0,         -- 是否敏感笔记 (0/1)
    is_favorite     INTEGER DEFAULT 0,         -- 是否收藏 (0/1)
    is_archived     INTEGER DEFAULT 0,         -- 是否归档 (0/1)
    content_hash    TEXT,                      -- 内容哈希 (用于同步检测)
    device_id       TEXT,                      -- 创建设备标识
    created_at      TEXT NOT NULL,             -- 创建时间
    updated_at      TEXT NOT NULL,             -- 最后更新时间
    deleted_at      TEXT,                      -- 软删除时间
    FOREIGN KEY (parent_id) REFERENCES folders(id),
    FOREIGN KEY (category_id) REFERENCES categories(id)
);

-- 索引
CREATE INDEX idx_notes_parent_id ON notes(parent_id);
CREATE INDEX idx_notes_category_id ON notes(category_id);
CREATE INDEX idx_notes_favorite ON notes(is_favorite);
CREATE INDEX idx_notes_created_at ON notes(created_at DESC);
CREATE INDEX idx_notes_updated_at ON notes(updated_at DESC);
CREATE INDEX idx_notes_deleted_at ON notes(deleted_at);
CREATE INDEX idx_notes_sensitive ON notes(is_sensitive);

-- 全文搜索索引 (FTS5)
CREATE VIRTUAL TABLE notes_fts USING fts5(
    title,
    content_text,
    content=notes,
    content_rowid=rowid
);
```

### 2.6 笔记版本表 (note_versions)

```sql
CREATE TABLE note_versions (
    id              TEXT PRIMARY KEY,          -- UUID
    note_id         TEXT NOT NULL,             -- 所属笔记 ID
    version         INTEGER NOT NULL,          -- 版本号 (自增)
    title           TEXT NOT NULL,             -- 版本标题
    content         TEXT,                      -- 版本内容 (JSON)
    content_text    TEXT,                      -- 版本纯文本
    summary         TEXT,                      -- 版本摘要
    change_message  TEXT,                      -- 修改说明 (可选)
    change_type     TEXT,                      -- 修改类型 (auto/manual)
    created_by      TEXT,                      -- 修改设备/用户
    created_at      TEXT NOT NULL,
    FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_note_versions_note_id ON note_versions(note_id, version DESC);

-- 触发器：笔记更新时自动保存版本
CREATE TRIGGER trg_notes_version_insert
AFTER UPDATE OF title, content ON notes
BEGIN
    INSERT INTO note_versions (id, note_id, version, title, content, content_text, change_type, created_at)
    SELECT
        lower(hex(randomblob(16))) || '-' ||
        substr(hex(randomblob(4)),1,4) || '-4' ||
        substr(hex(randomblob(4)),1,4) || '-a' ||
        substr(hex(randomblob(12)),1,4) || '-' ||
        hex(randomblob(6)),
        OLD.id,
        (SELECT COALESCE(MAX(version), 0) + 1 FROM note_versions WHERE note_id = OLD.id),
        OLD.title,
        OLD.content,
        OLD.content_text,
        'auto',
        datetime('now')
    WHERE OLD.title != NEW.title OR OLD.content != NEW.content;
END;
```

### 2.7 待办表 (todos)

```sql
CREATE TABLE todos (
    id              TEXT PRIMARY KEY,          -- UUID
    note_id         TEXT,                      -- 关联笔记 ID (可为空)
    title           TEXT NOT NULL,             -- 待办标题
    description     TEXT,                      -- 详细描述 (可选)
    status          TEXT DEFAULT 'pending',    -- 状态: pending/in_progress/completed/cancelled
    priority        INTEGER DEFAULT 2,         -- 优先级: 1=低/2=中/3=高
    due_date        TEXT,                      -- 截止日期 (ISO格式)
    remind_at       TEXT,                      -- 提醒时间
    completed_at    TEXT,                      -- 完成时间
    source          TEXT DEFAULT 'manual',     -- 来源: manual/ai_extract/voice
    parent_todo_id  TEXT,                      -- 子任务关联父待办 ID
    sort_order      INTEGER DEFAULT 0,         -- 排序权重
    is_deleted      INTEGER DEFAULT 0,         -- 删除标记
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE SET NULL,
    FOREIGN KEY (parent_todo_id) REFERENCES todos(id)
);

-- 索引
CREATE INDEX idx_todos_status ON todos(status);
CREATE INDEX idx_todos_due_date ON todos(due_date);
CREATE INDEX idx_todos_priority ON todos(priority);
CREATE INDEX idx_todos_note_id ON todos(note_id);
CREATE INDEX idx_todos_remind_at ON todos(remind_at);
CREATE INDEX idx_todos_parent_todo_id ON todos(parent_todo_id);
```

## 4. 枚举值定义

### 4.1 笔记状态

| 字段 | 值 | 说明 |
|------|-----|------|
| is_favorite | 0 | 未收藏 |
| is_favorite | 1 | 已收藏 |
| is_sensitive | 0 | 普通笔记 |
| is_sensitive | 1 | 敏感笔记 (加密+不上传) |
| is_archived | 0 | 未归档 |
| is_archived | 1 | 已归档 |
| deleted_at | NULL | 未删除 |
| deleted_at | 时间戳 | 已软删除 |

### 4.2 待办状态与优先级

| 字段 | 值 | 说明 |
|------|-----|------|
| status | pending | 待处理 |
| status | in_progress | 进行中 |
| status | completed | 已完成 |
| status | cancelled | 已取消 |
| priority | 1 | 低优先级 |
| priority | 2 | 中优先级 |
| priority | 3 | 高优先级 |

## 5. 数据生命周期管理

### 5.1 删除策略


```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   正常状态    │    │  回收站       │    │  彻底删除    │
│              │    │              │    │              │
│ 数据可见     │───▶│ deleted_at   │───▶│ 物理删除     │
│ 可编辑可搜索  │    │ 已设置       │    │ 30天后自动   │
│              │    │ 不可搜索     │    │ 或手动清空    │
└──────────────┘    └──────────────┘    └──────────────┘

流程说明:
1. 用户删除笔记 → 设置 deleted_at，移入回收站
2. 回收站中可恢复（清除 deleted_at）或彻底删除
3. 超出保留期(30天)自动物理删除
4. 物理删除同时级联删除: 版本历史、附件引用、标签关联
```

### 5.2 版本保留策略

| 策略 | 规则 |
|------|------|
| 自动版本 | 每次编辑保存时自动创建 (最多保留30个) |
| 手动版本 | 用户手动标记的重要版本 (永久保留) |
| 保留策略 | 超过30个自动版本时，删除最旧的 |
| 特殊处理 | 敏感笔记的版本同样加密存储 |

### 5.3 数据增长管理

| 数据类型 | 保留策略 | 清理规则 |
|----------|----------|----------|
| 笔记版本 | 30个/笔记 | 超出自动清理 |
| AI 对话 | 无限制 | 用户可手动删除 |
| 同步记录 | 90天 | 周期清理 |
| 日志 | 7天 | 周期清理 |
| 缓存图片 | 30天未访问 | 按需清理 |
| 向量索引 | 随笔记同步 | 笔记删除时更新 |
| 回收站 | 30天 | 超出自动清理 |

## 6. 数据迁移策略

### 6.1 数据库版本迁移

```typescript
// database.ts - 迁移策略
export const MIGRATIONS = [
    {
        version: 1,
        [sql]: CREATE TABLE notes (/* ... */)
    },
    {
        version: 2,
        [sql]: ALTER TABLE notes ADD COLUMN is_archived INTEGER DEFAULT 0;
    },
    {
        version: 3,
        [sql]: CREATE TABLE invoices (/* ... */)
    }
];
```

### 6.2 迁移原则

1. **向前兼容**：新版本 App 能读取旧版本数据
2. **不可逆性**：迁移仅向前，不回滚
3. **备份先行**：迁移前自动备份数据库
4. **失败回滚**：迁移失败恢复备份
5. **幂等性**：迁移操作可重复执行

## 8. 性能优化策略

### 8.1 索引优化

| 查询场景 | 关键索引 | 预期性能 |
|----------|----------|----------|
| 加载文件夹内笔记 | idx_notes_parent_id | < 50ms |
| 最近更新列表 | idx_notes_updated_at | < 50ms |
| 待办列表 (按状态) | idx_todos_status | < 30ms |
| AI 对话消息查询 | idx_ai_messages_conversation_id | < 30ms |
| 全文搜索 | notes_fts (FTS5) | < 200ms |
| 标签查询 | idx_note_tags_tag_id | < 30ms |

### 8.2 查询优化原则

1. 始终使用索引列作为 WHERE 条件
2. 使用 LIMIT 分页加载，避免全表扫描
3. 大数据量使用 PRAGMA cache_size 优化
4. 定期执行 VACUUM 回收空间
5. 复杂统计查询使用冗余字段缓存

## 9. 安全与加密

### 9.1 加密方案

```
┌─────────────────────────────────────────────────┐
│              加密层次架构                        │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │ SQLCipher (数据库级加密)                 │  │
│  │ - 全库 AES-256 加密                     │  │
│  │ - 密钥存储于系统 Keystore                │  │
│  └───────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────┐  │
│  │ 字段级加密                               │  │
│  │ - 敏感笔记 content_enc 字段             │  │
│  │ - 票据 OCR 原始数据                     │  │
│  │ - 语音转写原始文本                      │  │
│  └───────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────┐  │
│  │ 文件级加密                               │  │
│  │ - 图片/音频/附件文件                     │  │
│  │ - AES-GCM 加密                          │  │
│  │ - 密钥从主密钥派生                    │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### 9.2 密钥管理

| 密钥 | 用途 | 存储方式 |
|------|------|----------|
| 主密钥 (Master Key) | 解密数据库 | 系统 Keystore |
| 派生密钥 (Per-File) | 文件加密 | 主密钥派生 |
| 备份密钥 | 本地备份加密 | 用户设置或 Keystore |
| API Key | AI 服务认证 | Keystore (不存数据库) |
