# 变更运行服务器 · 技术使用手册

> 适用项目：note-demo（Expo SDK 57 / React Native 0.86）
> 目的：告诉你「此项目要变更运行服务器时，需要准备哪些资源、有哪些配置要求」，涵盖开发服务器、AI 接口、以及云端后端三类服务器。

---

## 0. 先分清这个项目有哪几种「服务器」

| 服务器类型 | 作用（大白话） | 现状 | 对应代码/配置 |
|-----------|--------------|------|--------------|
| **开发服务器 (Metro)** | 手机/模拟器加载 JS 代码就靠它，相当于「实时打包机」 | 已用，`start-wifi.cmd` / `start-fast.cmd` | `app.json`、启动脚本 |
| **AI 接口服务器** | 通义千问 / DeepSeek 的对话、分类、摘要能力 | 已用，写死在代码里 | `services/ai/*.client.ts` |
| **云端后端服务器** | 用户账号、多端同步、文件云存储 | 未上线（预留） | `docs/08-部署运维指南.md` |

> 注意：目前 App **没有真实的后端服务器**，笔记/待办都存在手机本地 SQLite 里。所以「变更服务器」最常见的诉求其实是**变更开发服务器地址**和**变更 AI 接口地址**，下面分三章讲清。

## 1. 变更「开发服务器」(Metro) 的地址

### 1.1 需要准备哪些资源

| 资源 | 要求 | 说明 |
|------|------|------|
| 一台「暴露 Metro」的电脑 | 有 Node.js + 项目源码 + 已 `npm install` | Metro 就是这个电脑跑起来的 |
| 局域网连通 | 手机和电脑连**同一个 WiFi**，能互相 ping 通 | 手机通过 `http://<电脑IP>:8081` 访问 |
| 端口 8081 可用 | 无其他程序占用 | 占用时需先 `taskkill` 或换端口 |
| （可选）域名/反代 | 若要跨公网访问，需 Nginx 等做端口映射 | 见 1.4 |

### 1.2 怎么改地址

**方式 A：改电脑 IP（局域网）**

把 Metro 跑起来时，电脑 IP 会决定最终地址。项目里已有一键脚本：

```
start-wifi.cmd          # 自动检测电脑 IP，后台起 Metro，打印连接地址
start-wifi.cmd adb      # 再用数据线连着时，自动通过 adb reverse 拉起 App
```

它最终会打印类似地址（手机填这个）：

```
http://192.168.1.100:8081
```

**方式 B：改监听端口（默认 8081）**

默认端口是 8081，要在 `start-wifi.cmd` 里改两处：

1. 第 16 行 `netstat ... findstr ":8081"` 里的 `8081`
2. 第 52 行 `echo      http://!IP!:8081` 里的 `8081`

> 若用 `npx expo start --port 9000` 手动起，则地址为 `http://<电脑IP>:9000`。

### 1.3 手机端怎么连新的开发服务器

打开 App 后进入 **Dev Launcher（开发客户端）**：

1. 点「Connect / 连接」
2. 手动输入新地址（如 `http://192.168.1.100:8081`）
3. 回车加载

> 数据线兜底方案：`adb reverse tcp:8081 tcp:8081` 后，App 直接访问 `localhost:8081` 即可，不受 WiFi 影响。

### 1.4 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 手机连不上「超时」 | 电脑防火墙拦了 8081 | Windows 防火墙放行 `node.exe` 或 8081 端口 |
| 手机能 ping 但 8081 不通 | 端口被占 / Metro 没起来 | 重跑 `start-wifi.cmd`，或换端口 |
| 电脑开了 `--lan` 手机仍连不上 | 手机和电脑不在同一网段 | 检查都连的是不是同一个路由器 |

## 2. 变更「AI 接口服务器」的地址

### 2.1 现状：地址写死在代码里

AI 接口地址是**硬编码常量**，不在配置文件里。位置：

| Provider | 文件 | 常量 | 默认值 |
|----------|------|------|--------|
| 通义千问 | `services/ai/qwen.client.ts` | `DASHSCOPE_BASE`（第 26 行） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| DeepSeek | `services/ai/deepseek.client.ts` | `DEEPSEEK_BASE`（第 26 行） | `https://api.deepseek.com` |

### 2.2 需要准备哪些资源

| 资源 | 要求 | 说明 |
|------|------|------|
| **目标服务器的 Base URL** | 必须兼容 OpenAI 的 `POST /chat/completions` 接口 | 两个 client 都是按 OpenAI 协议调用 + SSE 流式 |
| **API Key** | 目标服务器颁发的密钥 | 通过 `services/ai/keyStore.ts` 存进系统安全区 |
| **支持的模型名** | 新服务器支持的模型 ID | 例如 `qwen-turbo` / `deepseek-chat`，见各 client 的 `DEFAULT_MODEL` |
| **网络可达** | 手机能访问到新服务器 | 若换成本地/内网私有 AI 网关，手机需在同一网络 |

### 2.3 变更步骤

1. 打开对应 client 文件，把 `DASHSCOPE_BASE` 或 `DEEPSEEK_BASE` 改成目标地址。例如换到某 OpenAI 兼容网关：

   ```ts
   const DASHSCOPE_BASE = 'https://your-ai-gateway.example.com/v1';
   ```

2. 修改 `DEFAULT_MODEL`（如需换默认模型）。

3. 在 App 的「设置 → AI 配置」页填入新服务器的 API Key（key 存 `expo-secure-store`，不会明文落库）。

4. 重新加载/重新编译（改了原生无关的 TS 只需重载 JS；改了会打进 JS bundle）。

### 2.4 常见坑

| 坑 | 说明 | 处理 |
|----|------|------|
| 新服务器不是 OpenAI 兼容协议 | 请求格式不匹配会直接报错 | 需改对应 client 的 `request`/`chatStream` 请求体结构 |
| 流式响应格式不同 | 解析 `choices[0].delta.content` 假设了 OpenAI 格式 | 改 SSE 回调里的解析逻辑 |
| 敏感笔记外发 | `is_sensitive=1` 的笔记禁止发给 AI，换服务器**同样要遵守** | 不要绕过这条隐私规则 |

## 3. 变更「云端后端服务器」（预留，尚未上线）

### 3.1 现状说明

当前项目**没有**可运行的后端服务，`docs/08-部署运维指南.md` 里的 Nginx/Postgres/Redis/MinIO 架构是**前期设计文档**，代码尚未接入。若未来要启用，需按下面准备。

### 3.2 需要准备哪些资源

| 资源 | 要求 | 说明 |
|------|------|------|
| 服务器主机 | 2 核 4GB 起，Ubuntu 22.04 LTS | 见 `docs/08` 第 1.2 节 |
| 数据库 | PostgreSQL 14+ | 主数据存储 |
| 缓存 | Redis 6+ | 会话/限流 |
| 对象存储 | MinIO / S3 | 笔记附件云存 |
| 反向代理 | Nginx 1.20+ | HTTPS 终止 + 负载均衡 |
| 域名 + SSL 证书 | 需绑定 `api.note-demo.com` | HTTPS 必须 |
| 环境变量 | 见 `docs/08` 第 2.1 节完整清单 | DB/Redis/JWT/AI Key 等 |

### 3.3 配置要求（客户端侧要改的地方）

启用真实后端后，客户端需要：

1. **新增后端 Base URL 配置项**（当前代码无此配置，需新加，参考 `AIProviderConfig.baseUrl` 的预留字段思路）。
2. **改为可配置**，不要硬编码在业务代码里（学习 AI client 用 `baseUrl` 约定的方式）。
3. **HTTPS 强制**：生产环境一律走 `https`，避免明文传输。

> 这部分属于「未来改造」，现阶段只需知道：后端地址**尚未在客户端落地**，真正接入时优先做成可配置、走 HTTPS。

| 想变更 | 改哪里 | 是否要重新编译 |
|--------|--------|--------------|

## 5. 附：与「重新编译」的关系

- 只改**开发服务器地址 / 端口 / 手机连接方式** → **无需**重新编译原生，重连即可。
- 只改 **AI 接口地址 / 模型**（纯 TS）→ 开发模式改后 `Metro` 热重载即可生效；**若装的是发布版 APK，则必须重新执行**：

  ```
  cd android
  ./gradlew assembleRelease --init-script mirror.gradle
  ```

  > 说明：`--init-script mirror.gradle` 是因为当前网络访问 Google Maven 超时，需走阿里云镜像。（`mirror.gradle` 为编译辅助脚本，非项目业务文件。）
