# 技术实施方案：全局截图存笔记 / 抓链接存链接库

> 项目：note-demo（Expo SDK 57 / React Native 0.86）
> 状态：**已实现（三阶段代码落地 + 对抗性审查修复）**
> 前提结论：本需求**不需要无障碍服务**，用「系统分享 + 快速设置磁贴 + MediaProjection」即可实现，且为未来上架保留干净退路。
>
> **重要**：本文件前 7 章为原设计方案，第 8 章起为「实际落地结果 + 安全审查修复记录」。两者若有出入，以第 8 章为准。

## 0. 需求确认结果（回顾）

| 项 | 结论 |
|----|------|
| 核心动作 A | 对任意 App 截屏 → 存为「图片笔记 / 待办」（存前可编辑标题内容） |
| 核心动作 B | 读取当前 App 的跳转链接 → 存进「链接库 / 笔记」 |
| 链接范围 | 浏览器 URL + App 分享出来的内容链接 |
| 链接抓取期望 | 「尽力而为」：能抓到就存，抓不到退回截图 + 手动补链接 |
| 唤起方式 | 按需唤起（非常驻悬浮球） |
| 分发 | 短期内部装 APK，未来可能上架 |
| 无障碍 | **不需要**（已排除「模拟操作别的 App」这类需求） |

## 1. 总体技术路线

采用**三条系统级原生通道**，对应两个核心动作 + 一个兜底唤起：

| 能力 | 原生通道 | 触发的系统权限 | 备注 |
|------|---------|--------------|------|
| 抓链接（动作 B 主路径） | **Share Target（分享到 App）** | 无（系统机制） | 最可靠、最合规 |
| 截屏（动作 A 主路径） | **MediaProjection（屏幕录制单帧）** | `RECORD_SCREEN`（运行时弹系统框） | 与无障碍无关 |
| 一键唤起截屏 | **Quick Settings Tile（快速设置磁贴）** | 无 | 用户下拉通知栏点磁贴触发 |

> 理由：`Share Target` 是 Android 取「当前网页/App 分享出的链接」的标准且稳定通道，远比无障碍抓 `accessibilityNodeInfo` 可靠；截屏用 `MediaProjection` 也是系统正规能力。两者都**不触发无障碍服务**，避免商店审核高风险。

## 2. 分模块设计

### 2.1 动作 B：抓链接存链接库（Share Target）

#### 工作原理
1. 用户在任意 App（浏览器/微信/小红书等）点「分享」。
2. 系统分享面板中出现「note-demo」。
3. Android 通过 `Intent.ACTION_SEND` 把 `EXTRA_TEXT`（通常是 URL + 标题）传给 note-demo。
4. 应用捕获该 Intent，弹出「存为链接」确认页，写入链接库。

#### 需要的原生配置（在 `android/app/src/main/AndroidManifest.xml` 的 MainActivity 上加 intent-filter）

```xml
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="text/plain" />
</intent-filter>
```

> 说明：`text/plain` 能覆盖绝大多数「分享一段文字/链接」的场景。若也想收图片分享，另加 `image/*`，但这会引入图片接入逻辑，**建议一期只收 text/plain**。

#### Expo 侧接收 Intent
- 用 `expo-linking` 的 `Linking.getInitialURL()` / `Linking.addEventListener('url', ...)` 不一定能拿到 SEND Intent 的 `EXTRA_TEXT`。
- **更可靠做法**：自写一个轻量原生模块（或使用 `react-native-share-target` 类库），在 `MainActivity.onCreate` 里读 `intent.getStringExtra(Intent.EXTRA_TEXT)`，通过 Bridge / Event 回调给 JS。

#### 落到现有链接库
复用已存在的 `services/savedLink.service.ts`：
- 步骤：`SavedLinkService.saveLink({ url, title })` 已实现「同 url 查重更新、缺 title 兜底为 url」。
- 抓标题/缩略图：复用 `services/linkMeta.service.ts` 的 `fetchLinkMeta(url)`（已含 SSRF 防护，禁止本地/内网地址）。
- 存后跳转：`app/link/[id].tsx` 已有编辑页，可先弹确认再存。

#### 关键点 / 坑
- `EXTRA_TEXT` 可能是「纯 URL」也可能是「标题 + 换行 + URL」，需做一次 URL 抽取（正则匹配 `https?://...`）。
- 抓不到链接时（某些 App 只分享文字不含 URL）：走「截图 + 手动补链接」兜底（见 2.2）。
- 未来上架：Share Target 完全合规，无风险。

### 2.2 动作 A：截屏存图片笔记 / 待办（MediaProjection）

#### 工作原理
1. 用户点「快速设置磁贴」或 App 内按钮触发。
2. 弹出系统「是否允许录制屏幕」授权框。
3. 用 `MediaProjection` 抓取**一帧画面**（不是持续录屏）。
4. 把这一帧保存为 PNG，存进附件目录。
5. 跳转「图片笔记 / 待办」确认页，用户可改标题后保存。

#### 需要的系统权限
| 权限 | 类型 | 说明 |
|------|------|------|
| `FOREGROUND_SERVICE` | 清单声明 | MediaProjection 常要求前台服务 |
| `FOREGROUND_SERVICE_MEDIA_PROJECTION` | 清单声明 | Android 14+ 必须显式声明 |
| 屏幕录制授权 | 运行时弹框 | 每次触发由系统弹「开始录制/截屏」确认 |

#### Expo 侧实现选择
Expo 官方**没有**开箱即用的截屏模块，需走原生模块，两种方式：

- **方式 1（推荐，可控）**：自写 Expo Native Module，用 `MediaProjectionManager` + `ImageReader` 抓一帧 → 存文件 → 通过 `expo-file-system`（已有依赖）暴露文件路径给 JS。
- **方式 2（找现成库）**：`react-native-view-shot`（只能截自己 App，**不满足**「截别的 App」）—— ❌ 不适用。真机全局截屏需依赖 `MediaProjection` 自写或 `react-native-screen-recorder` 类库。

> 明确：`react-native-view-shot` 截的是「自己画面」，截不了别的 App。全局截屏必须 `MediaProjection`。

#### 落到现有笔记 / 待办
- 截图文件 → 复用 `src/utils/attachmentStorage.ts` 的 `persistImageAttachment()`，它会：持久化文件到 `attachments/` 目录 + 创建 `attachments` 记录。
- 存为「图片笔记」：调 `NoteService.createNote()`，附件挂在 `note_id` 下。
- 存为「待办」：调 `TodoService.createTodo()`，附件同样挂靠关联笔记。
- 存前可编辑：跳转 `app/note/[id]/edit.tsx`（已有富文本+图片）或新建一个轻量「截图确认页」。

#### 关键点 / 坑
- **Android 14+** 必须声明 `FOREGROUND_SERVICE_MEDIA_PROJECTION`，否则闪退。
- 「抓一帧」而非「持续录屏」能减少耗电和权限顾虑（用户看到的是"截图"而非"录屏"）。
- 截图 → 待办时，可复用已有 `services/ai/index.ts` 的 `extractTodosFromText()`，把截图交给 OCR/AI 提炼成待办（`attachment.service.ts` 已有 `ocr_text` / `ai_description` 字段承接）。这是**可选增强**，一期可不做 OCR，直接存图。

### 2.3 兜底唤起：快速设置磁贴（Quick Settings Tile）

#### 作用
用户下拉系统通知栏 → 点「note-demo 截图」磁贴 → 直接触发 2.2 的截屏流程。满足「按需唤起、不常驻悬浮球」。

#### 实现
- 原生 `TileService`（继承 `android.service.quicksettings.TileService`），在 `AndroidManifest.xml` 声明。
- 用户需手动把磁贴拖进快速设置面板（系统机制，首次使用提示一次）。

```xml
  android:permission="android.permission.BIND_QUICK_SETTINGS_TILE"
  android:exported="true">
  <intent-filter>
    <action android:name="android.service.quicksettings.action.QS_TILE" />
  </intent-filter>
</service>
```

### 3.2 app.json（Expo 侧）可能涉及
- 若自写原生模块，需在 `android/` 手工加代码（Expo 配置插件 `expo-build-properties` 只补 build 配置，不覆盖原生 Java/Kotlin 逻辑）。
- `android.permissions` 数组里补 `FOREGROUND_SERVICE` 与 `FOREGROUND_SERVICE_MEDIA_PROJECTION`（对应 `app.json` 第 29-36 行现有 permissions 块）。

### 3.3 依赖选型（新增原生能力时）

| 能力 | 推荐做法 | 是否新增 npm 依赖 |
|------|---------|------------------|
| Share Target 收文本 | 自写原生接收 + `expo-linking`（已有） | 可不加 |
| 全局截屏 | 自写 Expo Native Module（MediaProjection） | 可不加（写 Kotlin） |
| 快速设置磁贴 | 自写 TileService | 可不加 |
| OCR（可选） | 复用 AI 服务，无需新模块 | 否 |

> 结论：**三项能力都建议自写少量原生 Kotlin，不引入第三方悬浮/截屏库**，这样可控、合规、便于未来上架。

## 4. 实施步骤（分阶段）

### 阶段一：抓链接（快、风险低，先做）
1. 在 `AndroidManifest.xml` 给 MainActivity 加 `SEND` + `text/plain` intent-filter。
2. 在 `MainActivity.kt` 读 `EXTRA_TEXT`，抽取 URL，通过事件回传 JS。
3. JS 侧：接 URL → `fetchLinkMeta` 拿标题 → `SavedLinkService.saveLink` → 跳 `link/[id]` 确认页。
4. 真机验证：浏览器分享 → note-demo → 链接进链接库。

### 阶段二：全局截屏（中风险，核心动作 A）
1. 写 `MediaProjection` + `ImageReader` 抓一帧的 Kotlin Native Module。
2. 补 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PROJECTION` 权限。
3. JS 侧：拿到截图文件 → `persistImageAttachment` → 新建图片笔记/待办 → 跳确认页可编辑。
4. 真机验证：任意 App 里触发磁贴 → 授权 → 存档。

### 阶段三：磁贴入口 + 可选 OCR
1. 写 `TileService`，点磁贴触发截屏。
2. （可选）截图后调 `extractTodosFromText`（先 OCR 或用 AI 视觉）自动提炼待办，仍允许用户确认修改。

## 5. 风险与注意事项

| 风险点 | 说明 | 应对 |
|--------|------|------|
| 商店审核 | MediaProjection 权限对商店也敏感，但属「有正当用途」 | 短期不上架不受影响；未来上架需在 `DATA_SAFETY` 声明 |
| 手机 ROM 差异 | 部分国产 ROM 对磁贴/后台服务有限制 | 提供「App 内按钮」作为磁贴的兜底入口 |
| 敏感内容外发 | `is_sensitive=1` 笔记禁止发给 AI，截图→OCR/AI 流程**同样要遵守** | OCR/AI 前先校验来源，不把敏感图外发 |
| 链接抽不到 | 部分 App 分享不含 URL | 兜底：只存文字 + 截图 + 手动补链接 |
| Android 版本 | MediaProjection 前台服务要求随版本升级变化大 | 用 SDK 57 默认 target，逐步适配 14/15 |

---

## 6. 与「未来上架」的架构隔离建议

- 把「抓链接（Share Target）」作为**上架安全的核心**，长期保留。
- 把「全局截屏 + 磁贴」作为**内部增强能力**，代码上独立成模块，未来可通过对 `DATA_SAFETY` 申报或条件编译控制是否随商店版发布。
- 无障碍服务、模拟点击等超纲能力**不进入主线**，如未来需要，另起独立分支。

### 8.2 完整工作链路

**链路 A — 抓链接**：任意 App 分享 → note-demo（SEND）→ 原生抽 URL → `note-demo://save-link?url=&title=` → JS 校验/消毒 → 跳 `link/new`（预填）→ 用户确认 → `SavedLinkService.saveLink` 入库。

**链路 B — 截屏**：记一笔「截屏」或下拉磁贴 → 系统录制授权 → `MediaProjection` 抓一帧 → 存 PNG → `persistAttachmentFile` → 建 `is_sensitive=1` 图片笔记 → 跳详情页。

### 8.3 已修复的缺陷（第一性原理审查 + 对抗性审查）

| 编号 | 问题 | 修复 |
|------|------|------|
| BUG-1 | `AppContextActivityResultContract<Unit, …>` 的 `Unit` 不满足 `I : Serializable` → 编译失败 | 改用 `internal object ScreenCaptureInput : Serializable` |
| BUG-2 | 手动 `cont` 与 `launch()` 双重续接 → 授权后永久卡死 | 改用 `captureLauncher.launch(...)` 的 suspend 返回值 |
| BUG-3 | 截图返回裸路径缺 `file://` | 原生 `Uri.fromFile(file).toString()` |
| BUG-4 | MediaProjection result Intent 未保留 | 结果类型改为 `ProjectionResult(resultCode, data)`，用真实 result Intent |
| BUG-5 | URL 尾随 `.` 被误删 | trim 字符集移除 `.` |
| 问题-6 | `file_size` 恒为 0 | 用 `new File(filePath).size` 读真实大小 |
| 问题-8 | 磁贴冷启动时序风险 | `await initDB()` + 3 次重试（每次 500ms） |
| 问题-9 | 磁贴图标含黑色非单色 | 改为纯白单路径矢量图 |
| BUG-10 | plugin 模板 `$CAPTURE_TOKEN` 未插值 → Kotlin `const val` 编译错误 | 模板内改用 `${CAPTURE_TOKEN}` 显式插值 |

### 8.4 原生改动的托管控件（重要）

> **关键发现**：`expo prebuild` 会**清空并重建 `android/` 目录**（本项目 behavior 为 clean 重建），因此**直接手工改 `android/` 下的 Kotlin/Manifest 会在下次 prebuild 时全部丢失**。

因此阶段一/三的原生改动已改用 **Expo config plugin** 托管，由 `prebuild` 每次自动生成：

- 文件：`plugins/withNoteDemoNative.js`（注册在 `app.json` 的 `plugins` 末尾）
- 托管内容：
  - `MainActivity.kt`（SEND 分享接收 + `handleShareIntent`）
  - `NoteCaptureTileService.kt`（磁贴 + token）
  - `res/drawable/ic_tile_capture.xml`（磁贴图标）
  - `res/values/strings.xml` 的 `tile_label`
  - `AndroidManifest.xml` 的 SEND intent-filter + 磁贴 service 声明
- **未纳入托管的**：`modules/screen-capture/`（在 `android/` 之外，prebuild 不影响）、`android/mirror.gradle`（阿里云镜像编译脚本，每次 prebuild 后需重建）。

> 权限 `FOREGROUND_SERVICE_MEDIA_PROJECTION` 已写入 `app.json` 的 `permissions`，prebuild 会自动保留。

### 8.5 编译验证结果

- `npx expo prebuild --platform android` + `./gradlew assembleDebug --init-script mirror.gradle` → **BUILD SUCCESSFUL**。
- 产物：`android/app/build/outputs/apk/debug/app-debug.apk`（约 266 MB）。
- 3 条 deprecated 警告（非错误）：`getRealMetrics`/`defaultDisplay`（MediaProjection 抓屏标准用法）、`startActivityAndCollapse`（磁贴标准用法）。

## 9. 对抗性安全审查与加固

> 已识别并修复的对抗性风险，按严重度排序。

### 9.1 已修复

| 风险 | 等级 | 修复 |
|------|------|------|
| 未认证深链 `note-demo://capture` 可被任意 App/网页触发（钓鱼式授权 + 存储轰炸） | 🔴 高 | 磁贴深链带内部 `token`，JS 校验通过才直达；无/错 token 走确认框 |
| 截屏默认存成 `is_sensitive=0`，违反隐私承诺（进导出/未来进 AI） | 🔴 高 | 截图笔记默认 `is_sensitive: 1` |
| `save-link` 的 `title` 未显式消毒 | 🟡 中 | `sanitizeRichHtml(title).slice(0,200)` + URL 协议白名单 |
| 深链去重键用完整 URL，可被 query 变化绕过 | 🟡 中 | 去重改为 `hostname` + 2 秒冷却 |

### 9.2 安全取舍（重要，读改动前必看）

1. **token 是非加密常量，不是签名**。`CAPTURE_TOKEN = "note-demo-tile-capture-v1"` 硬编码在两处：
   - `android/.../NoteCaptureTileService.kt` 的 `companion object`
   - `app/_layout.tsx` 顶部的 `CAPTURE_TOKEN`
   - 它只能挡住「外部 App/网页伪造触发」（普通 App 拿不到你的源码常量），**挡不住反编译 APK 拿到字符串后的伪造**。
   - 对「内部使用、短期不上架」场景足够；若需更高强度，应升级为：运行时生成一次性 token、或校验调用方 `getCallingPackage()` / `Activity.getReferrer()`。
2. **要改 token 值，必须同步改以上两处**，否则磁贴会因 token 不匹配而退化成「外部来源需确认」，甚至失效。
3. 磁贴 `android:exported="true"` 是 QS 磁贴的标准要求，靠 `BIND_QUICK_SETTINGS_TILE`（系统级权限）保护，属安全。
