# note-demo 部署运维指南

## 1. 部署架构

### 1.1 整体部署架构

```
┌─────────────────────────────────────────────────────────────┐
│                    客户端 (Android APK)                    │
│              React Native + Expo 应用                      │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTPS
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                   负载均衡 / API 网关                      │
│                  Nginx + SSL 终止                          │
└──────────┬──────────────────┬──────────────────┬───────────┘
           ▼                  ▼                  ▼
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│  同步服务        │  │  用户服务        │  │  AI 代理服务     │
│  Node.js/Python │  │  Node.js/Python │  │  Node.js/Python │
└────────┬────────┘  └────────┬────────┘  └────────┬────────┘
         │                   │                   │
         ▼                   ▼                   ▼
┌─────────────────────────────────────────────────────────────┐
│              PostgreSQL + Redis + MinIO/S3                │
└─────────────────────────────────────────────────────────────┘
```


### 1.2 部署环境要求

| 环境 | 配置 | 说明 |
|------|------|------|
| 服务器 | 2核 4GB 起 | 单机部署 |
| 操作系统 | Ubuntu 22.04 LTS | 推荐 |
| 数据库 | PostgreSQL 14+ | 主数据存储 |
| 缓存 | Redis 6+ | 会话/缓存 |
| 对象存储 | MinIO / S3 | 文件存储 |
| 反向代理 | Nginx 1.20+ | 负载均衡+SSL |
| 容器 | Docker + Docker Compose | 推荐部署方式 |

### 2.2 Docker Compose 配置

```yaml
version: '3.8'

services:
  api:
    build: ./backend
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DB_HOST=postgres
      - REDIS_HOST=redis
    depends_on:
      - postgres
      - redis
    restart: unless-stopped

  postgres:
    image: postgres:14
    environment:
      - POSTGRES_DB=note_demo
      - POSTGRES_USER=note_app
      - POSTGRES_PASSWORD=<password>
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:6
    command: redis-server --requirepass <password>
    volumes:
      - redisdata:/data
    restart: unless-stopped

  minio:
    image: minio/minio
    command: server /data --console-address :9001
    ports:
      - "9000:9000"
      - "9001:9001"
    environment:
      - MINIO_ROOT_USER=<access_key>
      - MINIO_ROOT_PASSWORD=<secret_key>
    volumes:
      - miniodata:/data
    restart: unless-stopped

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - api
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
  miniodata:
```


### 2.3 Nginx 配置

```nginx
server {
    listen 443 ssl;
    server_name api.note-demo.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    location / {
        proxy_pass http://api:3000;
        proxy_set_header Host System.Management.Automation.Internal.Host.InternalHost;
        proxy_set_header X-Real-IP ;
        proxy_set_header X-Forwarded-For ;
        proxy_set_header X-Forwarded-Proto ;
        proxy_read_timeout 60s;
    }

    # 文件上传大小限制
    client_max_body_size 50m;
}

server {
    listen 80;
    server_name api.note-demo.com;
    return 301 https://System.Management.Automation.Internal.Host.InternalHost;
}
```

## 4. CI/CD 配置

### 4.1 CI/CD 流程

```
代码提交 -> 自动构建 -> 自动测试 -> 自动部署
    |          |            |            |
    v          v            v            v
  Git Push   Build       Test        Deploy
             (Expo)     (Jest)      (APK/后端)
```

### 4.2 GitHub Actions 配置

```yaml
name: CI/CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: 18
      - run: npm ci
      - run: npm test
      - run: npm run lint

  build-android:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: 18
      - run: npm ci
      - run: npx expo prebuild --platform android
      - run: cd android && ./gradlew assembleRelease
      - uses: actions/upload-artifact@v3
        with:
          name: app-release.apk
          path: android/app/build/outputs/apk/release/

  deploy-backend:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v3
      - name: Deploy to server
        uses: appleboy/ssh-action@v0.1.5
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_KEY }}
          script: |
            cd /opt/note-demo
            git pull
            docker-compose up -d --build
```

## 6. 备份与恢复

### 6.1 备份策略

| 数据 | 备份方式 | 频率 | 保留 |
|------|----------|------|------|
| PostgreSQL | pg_dump | 每日 | 30天 |
| 文件存储 | MinIO 同步 | 每日 | 30天 |
| 配置 | Git 版本控制 | 每次变更 | 永久 |
| 环境变量 | 加密存储 | 每次变更 | 永久 |

### 6.2 备份脚本

```bash
#!/bin/bash
# 每日备份脚本
BACKUP_DIR=/backups/note-demo
DATE=$(date +%Y%m%d)

# 备份数据库
pg_dump -h localhost -U note_app note_demo | gzip > $BACKUP_DIR/db_$DATE.sql.gz

# 备份文件存储
mc mirror --overwrite local/note-demo-files $BACKUP_DIR/files_$DATE/

# 清理30天前的备份
find $BACKUP_DIR -name "db_*.sql.gz" -mtime +30 -delete
find $BACKUP_DIR -name "files_*" -mtime +30 -exec rm -rf {} ;
```


## 7. 安全运维

### 7.1 安全措施

| 措施 | 说明 |
|------|------|
| HTTPS | 全站 TLS 1.2+ |
| 密码策略 | 最小12位，含大小写+数字+特殊字符 |
| 登录限流 | 5次失败锁定15分钟 |
| API 限流 | 每用户 100次/分钟 |
| 密钥管理 | 环境变量 + 密钥管理服务 |
| 安全更新 | 每月检查依赖更新 |
| 审计日志 | 记录敏感操作 |
| 防火墙 | 仅开放 80/443/22 端口 |

### 7.2 安全更新流程

1. 每月检查依赖安全公告
2. 使用 npm audit / pip-audit 扫描
3. 紧急漏洞 24h 内修复
4. 更新后执行回归测试

## 8. 故障处理

### 8.1 常见故障处理

| 故障 | 症状 | 处理步骤 |
|------|------|----------|
| 服务不可用 | 502/503 | 检查 Docker 状态 -> 查看日志 -> 重启服务 |
| 数据库连接失败 | 500 错误 | 检查 PostgreSQL 状态 -> 检查连接数 -> 重启 |
| 磁盘空间不足 | 服务异常 | 清理日志 -> 清理备份 -> 扩容 |
| 内存溢出 | 服务崩溃 | 查看内存监控 -> 优化配置 -> 扩容 |
| 同步冲突 | 数据不一致 | 查看冲突日志 -> 手动解决 -> 通知用户 |
| AI 服务不可用 | 功能降级 | 切换备选 Provider -> 通知用户 |

### 8.2 应急响应流程

```
发现故障 -> 评估影响 -> 通知相关人员
    |
    v
紧急修复 -> 验证 -> 恢复服务
    |
    v
事后分析 -> 记录 -> 改进
```
